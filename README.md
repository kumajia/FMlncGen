# FMlncGen — .lnc コードジェネレーター

Football Manager のクラブ名・大会名・選手名・スタジアム名を日本語カタカナに自動翻訳し、`.lnc` コードを生成するツールです。
ブラウザだけで動作し、データはあなたの端末から外に出ません（翻訳・画像抽出・モデル一覧の取得のときだけ、選んだ AI プロバイダの API と通信します）。
翻訳・画像抽出は **Google Gemini** と **Groq** のどちらでも使えます。

- 公開版: https://kumajia.github.io/FMlncGen/
- English: [README_EN.md](README_EN.md)
- 画面表示の版: v2.0.0（変更履歴は [CHANGELOG.md](CHANGELOG.md)）

## 使い方

画面の配置は UI レイアウト（後述）ごとに異なりますが、手順と各ボタンの名前はどのレイアウトでも同じです。見出しやナビの「接続」「入力」「レビュー」「出力」「辞書」を手がかりにしてください。

1. **接続を設定する**: 公開版の URL（または `index.html`）をブラウザ（Chrome / Edge 推奨）で開き、「AI 接続」で **APIプロバイダ**（Gemini / Groq）を選んで、対応する **APIキー**を入力します（取得方法は後述）。キーを入れると利用可能なモデルの一覧が自動で読み込まれます。
2. **入力する**: **対象**（クラブ名 / 大会名 / 選手名 / スタジアム名）を選び、データを貼り付けます。スクリーンショットから読み取ることもできます。
3. **変換する**: 「解析して翻訳開始」を押します。辞書にある語は辞書で、残りは AI で訳します。
4. **訳を確認・修正する**: レビューの表で訳を確認し、必要なら直します。黄色は AI 訳か新しい語です。直した訳は「手動編集をユーザー辞書に保存」で次回から再利用できます。
5. **.lnc を保存する**: 「.lncコード生成」を押し、「クリップボードにコピー」または「.lncファイルで保存」を選びます。

※ データは手入力のほか、**スクリーンショットから抽出**することもできます。FMの画面の画像を読み込ませると、名前とIDを自動で読み取って入力欄に追加します（選択中のプロバイダで処理されます。読み取り精度は Gemini の方が無難です）。

## UI レイアウトと配色テーマ

同じ機能を 7 種類の画面構成から選べます。どれを選んでもできることは同じです。

| レイアウト | 特徴 |
|---|---|
| Matchday Desk | 既定。放送卓風の標準案で、スコアボードと試合日程表のようなレビュー |
| Split Studio | 行番号つきエディタと表計算風レビューの 3 分割ワークベンチ。接続設定と辞書は引き出し（ドロワー）で開く |
| Kickoff Guide | 線でつながる手順と大きな質問カードで、1 画面ずつ進む |
| Command Deck | 等幅の端末型。`Ctrl+K`（Mac は `Cmd+K`）でコマンドパレット、`/` で入力欄へ移動、`Ctrl+Enter` で実行 |
| Review Board | チャット風の入力欄と確認カード。出力はレシート風 |
| Clubhouse Rail | 紺と金のクラブレール（ナビ）で 1 画面ずつ切り替えるアプリ型 |
| Programme | 明朝の章立てとメンバー表で、紙の試合プログラムのような構成 |

- **選び方**: どのレイアウトにもあるレイアウトのアイコンボタン（読み上げ名「UIレイアウトを選ぶ」）を押すと「表示の設定」が開きます。設定欄に「UIレイアウト」ボタンがあるレイアウトでは、そこからも開けます。Command Deck ではコマンドパレットの「UIレイアウトを選ぶ」でも開けます。
- **切り替え**: カードを選ぶとすぐにその画面へ切り替わります。「表示の設定」は開いたままなので、閉じるボタンか `Esc` で閉じてください。
- **切り替えても作業は消えません**: 入力中のデータ、修正中の訳、生成した `.lnc`、辞書の検索条件はそのまま引き継がれます。切り替えだけで翻訳やモデルの再取得が始まることはありません。
- **配色テーマ**: 「表示の設定」の「配色テーマ」で **自動 / ライト / ダーク** を選べます。レイアウトとは独立した設定で、「自動」は OS やブラウザのライト／ダーク設定に従います。
- **再読み込み後の復元**: 選んだレイアウトとテーマはブラウザに保存され、再読み込みや次回の起動でも同じ表示で開きます。

## 生成される .lnc コード

「対象」で選んだ種類に応じて、出力するコードが切り替わります。

**クラブ（対象＝クラブ名）** — LONG / SHORT の2行

| コード | 内容 | 例 |
|---|---|---|
| `CLUB_LONG_NAME_CHANGE` | 日本語カタカナのクラブ名 | `ヴィキングル レイキャヴィーク` |
| `CLUB_SHORT_NAME_CHANGE` | 短縮表示用の名前 | `ヴィキングル` |

**大会（対象＝大会名）** — LONG / SHORT の2行

| コード | 内容 |
|---|---|
| `COMP_LONG_NAME_CHANGE` | 日本語カタカナの大会名 |
| `COMP_SHORT_NAME_CHANGE` | 短縮表示用の名前 |

**選手（対象＝選手名）** — 1行（全言語に適用）

```
"CHANGE_PLAYER_NAME" 45 "" "パオロ マルディーニ"
```

**スタジアム（対象＝スタジアム名）** — 1行

```
"STADIUM_NAME_CHANGE" 102618 "セルティック パーク"
```

クラブ・大会の LONG 名は翻訳結果（＋プレフィックス）がそのまま入ります。
SHORT 名はテーブルの「SHORT名」列で個別に編集でき、**空欄のままにすると LONG と同じ値**で出力されます。順位表や試合画面などで短い名前を使いたいものだけ入力すれば十分です。
選手・スタジアムは SHORT を持たないため、SHORT列は表示されません。

FC / KVK / RES / VV / SV などのフットボール略語・頭字語はプレフィックスとして自動検出され、翻訳されずにそのまま残ります。

## 入力フォーマット

1行につき「名前（＋プレフィックス）＋ 末尾に半角スペース区切りの数値ID」を貼り付けます。

```
KE Wervik 539859
Wanze Bas Oha 132456
```

- 行末の数字がIDとして認識されます。
- 先頭の連続した大文字略語（FC など）はプレフィックスとして扱われます。

## 国名ヒントで現地読みに寄せる（クラブ名）

クラブ名の翻訳では、**国名を手がかりに、その国の言語の発音へ近づけたカタカナ**にできます（例: セルビアのクラブはセルビア語寄りの読みに）。

一番かんたんなのは、**クラブ名・ID・国名が一緒に表示されている画面のスクリーンショット**を読み込ませる方法です。下のような画面を撮って読み込ませると、国名を自動で読み取り、翻訳のヒントに使います。

![国名が表示された画面の例](country-example.png)

- スクショ抽出は `クラブ名 [国名] ID` の形式で書き出します（例: `Komgrap [セルビア] 5745713`）。
- 手入力でも `[国名]` を付ければ同じヒントになります。
- `[国名]` は翻訳のヒントに使うだけで、生成される `.lnc` には含まれません。
- 国名が無い行は、従来どおり綴りから言語圏を推測します。

> 国名が分かっても現地読みが完璧になるわけではありません（AIの推測のため外すこともあります）。気になるものは手で直して辞書に登録すると確実です。

## APIキーの取得

翻訳・画像抽出には、Gemini か Groq のキーを使います（どちらか、または両方を入力可）。

**Gemini**
1. https://aistudio.google.com を開く
2. 「Get API key」からキーを作成
3. アプリの「Gemini APIキー」欄に貼り付け

**Groq**
1. https://console.groq.com を開く
2. API Keys から「Create API Key」でキーを作成（`gsk_...`）
3. **作成直後に1度だけ表示される全文**をコピーし、アプリの「Groq APIキー」欄に貼り付け

※ プロバイダ選択で、翻訳・画像抽出にどちらを使うか切り替えます。
※ キーは各自で取得してください。他人のキーを使うと、その人の利用枠を消費します（条件によっては料金が発生します）。
※ 料金・無料枠の有無・利用上限は、各プロバイダの条件によって決まり、変わることがあります。最新の条件は各プロバイダの案内で確認してください。
※ キーはあなたのブラウザの localStorage に保存されます。FMlncGen は入力内容やキーを受け取るサーバーを持たず、キーは選んだプロバイダ（Google / Groq）の API にだけ送られます。
※ 画像（スクショ）の読み取り精度は Gemini の方が無難です。

## モデル一覧

- APIキーを入力すると、入力が落ち着いたところで、選んでいるプロバイダのモデル一覧 API から、翻訳に使える生成モデルを自動で読み込みます。プロバイダを切り替えたときや、キーを保存した状態で開いたときも読み込みます。
- 「モデルを再取得」ボタンで手動で読み直せます。読み込み中にもう一度押しても二重には取得しません。
- 選んでいたモデルが新しい一覧にあれば、その選択を保ちます。
- 取得に失敗したとき（キーの誤り、通信エラー、15 秒以上応答が無いときなど）は、それまでの候補と選択がそのまま残り、そのまま使えます。
- 一覧の取得にはキーとネットワークが必要です。キー欄が空なら通信しません。
- 一覧に出ていても、無料枠・残りの利用量・翻訳の成功は保証されません（残りの無料枠や利用上限は判定できません）。

## 停止・再実行とタイムアウト

- 翻訳中・画像抽出中は「停止」ボタンが表示されます。押すとその場で待機をやめ（レート制限の待機中でも止まります）、途中までの結果が残ります。続けて「解析して翻訳開始」を押せば、すぐにもう一度実行できます。
- 「解析して翻訳開始」の二度押しや連打では、翻訳は 1 回だけ実行されます。
- 画像抽出も 1 度に 1 本だけです。抽出中にもう一度押しても新しい抽出は始まりません。抽出中に画像をクリア・削除・追加すると、その抽出は中断され、結果は入力欄に入りません（実行中の翻訳は止まりません）。
- 1 回の要求が応答しないときの上限は、翻訳が **90 秒**、画像抽出が **120 秒**です。上限で打ち切った要求は自動で再送しません。
- 停止やタイムアウトは、ブラウザ側で応答を待つのをやめるだけです。プロバイダ側の処理が止まることや、課金・無料枠の消費が取り消されることは保証されません。

## 辞書とユーザー辞書

- **内蔵辞書はありません**: v2.0.0 で内蔵辞書を廃止しました。辞書で訳されるのは、あなたがユーザー辞書に保存した語（辞書マネージャーに取り込まれた語を含みます）だけです。それ以外は AI で訳します。
- **ユーザー辞書**: レビューの表で直した訳を「手動編集をユーザー辞書に保存」で、確定した訳をまとめて「全件を辞書に追加」で登録できます。登録した語は次回から AI を使わずに訳され、APIキーが無くても変換できます。データはこのブラウザ（このサイトのデータ）に保存されます。
- **旧版からの移行**: 同じサイトで旧版を使っていた場合、旧版で保存したユーザー辞書はそのまま使われます。旧版で作った作業を開き直すと、旧版で作られた訳は「要確認」になり、訳し直すか行ごとに「確認」を押すまで `.lnc` には出力されません（前回の出力欄は復元されず、元のデータは退避して保存されます）。
- **辞書のダウンロード・インポート**: 「辞書をダウンロード」「辞書をインポート」は、ユーザー辞書（原語→訳）を JSON で保存・読み込みします。別のPCへの移行やバックアップに使えます。辞書が空のときは、選んだファイルをそのまま取り込みます。既に辞書があるときは、取り込み方を選ぶ画面が開きます（[次の節](#辞書があるときのインポート統合置き換えキャンセル)）。

### 辞書があるときのインポート（統合・置き換え・キャンセル）

既に辞書がある状態で「辞書をインポート」からファイルを選ぶと、「辞書のインポート」画面が開き、現在の件数とファイルの件数が表示されます。取り込み方を次の 3 つから選びます。

| ボタン | 結果 |
|---|---|
| 統合する | 既存の辞書に追加します。同じ原語はファイルの訳で上書きします。それ以外の既存の語は残ります。上書きした語は、この後の変換でもファイルの訳で訳されます（辞書マネージャーには前の訳の記録も残ります）。 |
| 置き換える… | 既存の辞書を削除して、ファイルの内容だけにします。実行する前に、もう一度確認します（下記）。 |
| キャンセル | 何も変更しません。 |

> 更新の前から開いていたタブでは、この画面ではなく前の版の確認ボックス（「OK」と「キャンセル」だけ。「キャンセル」も置き換え）が出ることがあります。インポートの前に「[辞書をインポートする前に](#辞書をインポートする前に前の版の確認に注意)」を読んでください。

- `Esc` や閉じるボタン（×）で画面を閉じた場合も、キャンセルと同じく何も変更しません。
- 「置き換える…」を選ぶと「既存の辞書を置き換えますか？」という確認が開きます。「N 件を削除して置き換える」を押したときだけ置き換えます。この確認で「キャンセル」・`Esc`・閉じるボタンを使った場合も、何も変更しません。
- この 2 つの画面（取り込み方を選ぶ画面と置き換えの確認）では、画面が開いた直後（約 0.5 秒）のマウス・タッチ・ペンでの押下と、続けて押している間の押下（ダブルクリック・ダブルタップの 2 回目、連打）は、その画面の答えとして扱いません。押している途中にキーボードを押しても同じです。押し続けたキーの自動リピートも答えにしません。画面を読んでから、改めてボタンを押してください。
  - キーボードで新しく押した Enter・Space と、`Esc` はすぐに働きます。
  - 0.5 秒は固定です。OS で設定したダブルクリックの速さには合わせません。
  - 支援技術からボタンを実行した場合も、開いた直後はマウスの押下と同じく無視されることがあります。そのときはもう一度実行してください。
- 置き換えは元に戻せません。今の辞書を残したい場合は、キャンセルして先に「辞書をダウンロード」で保存してください。
- 置き換わるのは、このブラウザのユーザー辞書（「辞書をダウンロード」で保存される内容）だけです。APIキー・作業中の内容・表示の設定は変わりません。
- 変換を実行するたびに、その時点でユーザー辞書にある語はすべて[辞書マネージャー](#辞書マネージャー)にも取り込まれます。その変換で使われなかった語も含みます。取り込まれた語は置き換えでは削除されず、置き換えた後の変換でも使われることがあります。
  - 例: ユーザー辞書に Wervik と Ypres がある状態で、無関係な「Zulte Town」だけを変換します。その後 Geel だけの辞書で置き換えても、Wervik と Ypres は辞書マネージャーに残り、次の変換では置き換える前の訳で訳されます。
  - 一度も変換していない間にユーザー辞書へ入れた語は、辞書マネージャーに取り込まれていないので、置き換えで消えます。
- ファイルの読み込み中や、この画面を開いている間に別の辞書ファイルを選んでも受け付けません（2 つのインポートが混ざることはありません）。終わってから選び直してください。
- 読み込めないファイル（JSON でない、形式が違う、有効な項目が無い）のときは、エラーを表示して何も変更しません。

### 辞書マネージャー

登録した訳を検索・編集する画面です。

- **開き方**: 「辞書」（ユーザー辞書の管理）の欄にある「辞書マネージャー」ボタンを押します。ナビやツールバーに「辞書」があるレイアウトでは、そこから辞書の画面へ移ると辞書マネージャーも開きます。
- **一覧**: 開いた直後は、最近の項目が並びます。変換を実行したときにユーザー辞書にあった語は、その変換で使われなかった語も含めて、ここに表示されます（旧版で保存した語も同じです）。
- **検索**: 検索欄に入力して **Enter** を押すと検索します（入力しただけでは検索しません）。「検索対象・照合」で次を選べます。
  - 原語（前方一致）… 既定
  - 読み（前方一致）… カタカナの読みで探すとき
  - 原語（完全一致）
  - 別名
  - 最近
- **解除**: 検索欄で **Esc** を押すか「検索を解除」を押すと、検索語が消えて最近の一覧に戻ります（照合の選択はそのまま）。
- **行の操作**: 詳細 / ロック・解除 / 値を編集 / 論理削除（削除した行は「復活」で戻せます）/ 無効化。
- **バックアップ**: 辞書マネージャーの「完全バックアップをダウンロード」で、マネージャーの記録をまるごと保存できます。大きな変更の前に取っておくと安心です。

辞書マネージャー内の表示は日本語と英語です（他の UI 言語では英語で表示されます）。

### fm_dictionary.json について

`fm_dictionary.json` は、旧版（v1.x）向けに配布していたインポート用の初期辞書です。

- 現行版（v2.0.0）はこのファイルを読み込みません。旧版との互換のためにリポジトリに残しています。
- このファイルをインポートすると、中の訳があなたのユーザー辞書に入り、自分で確認した訳と同じように AI 訳より優先されます。v2.0.0 で廃止した古い訳が戻ることになるので、通常はインポートしないでください。

## アプリとしてインストール（PWA）・オフライン

Web上（GitHub Pages など）で開くと、ブラウザのアドレスバーに表示される
インストールアイコンから、独立したデスクトップアプリとして導入できます。

- **初回はネットワークが必要です**: 最初に開いたときに、オフライン用のファイルを準備します。
- **オフラインで使えるもの**: 一度オンラインで開いて準備が済めば（インストールした場合も同じ）、オフラインでも次が使えます。
  - ユーザー辞書による変換と `.lnc` の生成・保存
  - 辞書マネージャー（検索・編集）
  - UI レイアウトと配色テーマの選択・切り替え
- **ネットワークが必要なもの**: AI 翻訳、画像抽出、モデル一覧の取得（いずれも APIキーも必要）。

### 更新されたとき

- 新しい版が公開された直後は、最初に開いた画面が前の版のままのことがあります。その場合はページを再読み込みしてください。1 回の再読み込みでは切り替わらないこともあります。そのときは、少し待ってから再読み込みするか、FMlncGen を開いているタブやウィンドウ（インストールしたアプリを含む）をすべて閉じてから開き直してください。
- 更新の前から開いていたタブは、再読み込みするまで前の版のまま動きます。
- **再読み込みで消えるもの**: 作業内容は、変換（「解析して翻訳開始」）、レビューの表での修正、`.lnc` の生成・読み込みをしたときに保存されます。ただし表で訳を打ち直したときは、すぐには保存されず、最後に入力してから少したって（約 0.8 秒後）保存されます。打ち直した直後に再読み込みすると、その修正が消えることがあります。保存の後で入力欄に入れた文字や、出力欄で手で直した内容は、再読み込みすると消えます。変換した結果、保存済みの表の修正、生成した `.lnc` は戻ります。再読み込みは作業の区切りで行い、残したい原文や手直しは、その前にテキストエディタなどにコピーして保存してください。
- 画面の版表示は v2.0.0 のままで、レイアウトのアイコンボタン（「UIレイアウトを選ぶ」）も前の版からあるため、これらでは新しい版かどうかを見分けられません。
- 更新のためにブラウザのデータ（サイトデータ・キャッシュ）を削除する必要はありません。サイトデータを削除すると、ユーザー辞書・作業内容・APIキー・表示の設定も消えます。

#### 辞書をインポートする前に（前の版の確認に注意）

2026-10-08 までに公開した版では、既に辞書がある状態でインポートすると、ブラウザの確認ボックス（「OK」と「キャンセル」の 2 つのボタンだけ）が出ます。このボックスでは「OK」が統合、**「キャンセル」が置き換え**（今の辞書を削除して、ファイルの内容だけにする）です。どちらを押しても辞書は変わり、インポートをやめるボタンはありません。新しい版では、代わりに「統合する／置き換える…／キャンセル」の 3 つのボタンがある画面が出て、「キャンセル」では何も変わりません（[辞書があるときのインポート](#辞書があるときのインポート統合置き換えキャンセル)）。

- 更新の前から開いていたタブでは、インポートする前にページを再読み込みしてください（上の「再読み込みで消えるもの」に注意）。
- 1 回の再読み込みで新しい版になるとは限りません。インポートの前に「辞書をダウンロード」で今のユーザー辞書をファイルに保存しておくと、手元に残せます（ダウンロードしても辞書は変わりません）。
- インポートで「OK」と「キャンセル」だけの確認ボックスが出たら、それは前の版です。「キャンセル」は中止ではなく置き換えです。
- 辞書が空のときは、どちらの版でも確認なしにそのまま取り込みます。

## 注意事項

- 翻訳はAIによる音訳のため、公式表記と異なる場合があります。生成後にテーブルで確認・修正してから適用してください。
- 生成された `.lnc` は、FM の `…/Shared/Database/DB/<バージョン>/LNC/All` フォルダに置いて使います（`<バージョン>` は使用中のFMに対応するフォルダ。実際にDBフォルダ内にある番号を選んでください）。同名の `.lnc` を既に置いている場合は上書きされるので、必要なら事前に控えておいてください。
- 選手名は言語別に分けられない仕様のため、入力した名前が全言語で適用されます。
- スタジアム名は FM のバージョンや対象によっては反映されない場合があります（FM側の仕様）。

## 入力チェック・改行・エラーログ

- 解析時に、末尾の数値IDが取れない行は「読み取れなかった行」として警告表示します（その行はスキップされます）。
- 同じIDが複数行にある場合は「重複ID」として警告します。意図しない上書きを防ぐため、生成前に確認してください。
- `.lnc` の保存・コピー時は、FM標準の **CRLF（`\r\n`）改行**で書き出します（UTF-8・BOMなし）。
- 名前に含まれるダブルクォートなど `.lnc` を壊す文字は、生成時に自動で除去します。
- AI 翻訳に失敗した行や「要確認」の行は `.lnc` に出力しません。訳を入力するか、訳し直してください。
- 動作中にエラーが起きた場合、「エラーログ」ボタンから内容を `.log` ファイルとして保存できます。不具合報告に添付すると原因の特定に役立ちます。

## 便利機能

- **クラブ / 大会 / 選手 / スタジアムの切り替え**: 「対象」で切り替えると、出力コードが `CLUB_…` / `COMP_…` / `CHANGE_PLAYER_NAME` / `STADIUM_NAME_CHANGE` に変わります。いずれも翻訳・スクショ抽出に対応（SHORT名はクラブ・大会のみ）。
- **APIプロバイダ切替**: 翻訳・画像抽出に Gemini / Groq を選べます。画像（スクショ）の読み取り精度は Gemini が無難です。
- **利用可能モデルの自動取得**: APIキーを入力すると、利用可能な生成モデルを自動で読み込みます。「モデルを再取得」ボタンで手動更新もできます（[モデル一覧](#モデル一覧)参照）。
- **UI レイアウトと配色テーマ**: 7 種類の画面構成と、自動 / ライト / ダークの配色を選べます（[UI レイアウトと配色テーマ](#ui-レイアウトと配色テーマ)参照）。
- **バッチ翻訳**: 複数のクラブ名を1リクエストにまとめて翻訳（JSONで受け取り）し、API呼び出し回数を大幅に削減します。取りこぼした項目は自動で1件ずつ再翻訳します。バッチサイズは 15／20／10／1件 から選べます。
- **辞書だけで翻訳**: AI翻訳が必要な行が無ければ、APIキー無しでも実行できます。キーは「AIに投げる行があるとき」だけ要求されます。
- **重複の自動まとめ**: 同じクラブ名は1回だけ翻訳して使い回すため、API の呼び出し回数を減らせます。
- **作業の自動保存・復元**: 解析・翻訳・編集の内容は自動保存され、ブラウザを開き直すと前回の続きから復元できます。新しく始めるときは「クリア」。
- **翻訳・抽出の停止**: 翻訳中・画像抽出中に「停止」ボタンで中断でき、途中までの結果が残ります（[停止・再実行とタイムアウト](#停止再実行とタイムアウト)参照）。
- **全件を辞書に追加**: テーブルの有効な訳をまとめてユーザー辞書に登録できます（次回以降AIを使わず即翻訳）。
- **辞書マネージャー**: 登録した訳の検索・編集・ロック・バックアップができます（[辞書マネージャー](#辞書マネージャー)参照）。
- **.lncの読み込み**: 既存の `.lnc`（CLUB / COMP の LONG・SHORT）を読み込んでテーブルに展開し、修正してから再生成できます。読み込んだ内容に応じて対象が自動で切り替わります。
- **要対応のみ表示**: 翻訳が空・失敗の行だけに絞り込んで見直せます。

## データ協力

FMlncGen は**非営利のプロジェクト**です。

開発と互換性の検証のため、次のような最小限のデータについて、データ提供者と協力することがあります。

- Football Manager のクラブ ID
- 元の（原語の）クラブ名

このデータは、名前の解決と翻訳の互換性を検証するために使います。

第三者から提供されたデータは、**明示的な許可がない限り再配布しません**。希望があれば、提供されたデータセットを非公開のまま、開発と検証にだけ使うこともできます。

協力いただく場合は、次のような単純な対応表で十分です。

```text
fm_id,club_name
539859,KE Wervik
```

この用途では、ほかの項目は必要ありません。
